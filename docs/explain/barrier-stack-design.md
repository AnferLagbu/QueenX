# 栏栈架构设计

> 栏栈（Barrier Stack）的目标架构设计：从"恢复型栏栈"演进到"遏制 + 重建型栏栈"，以纯软件手段获得 MINIX 级的服务故障隔离能力。本文是设计立场文档，记录诊断结论、理论基础、架构形态与开放议题。

## 最初的想法与目标

### 缘起：为什么会有栏栈

栏栈的起点，来自 QueenX 对嵌入式 / IoT 场景的故障恢复诉求：**系统必须"跑起来就不宕机"**。初期的栏栈选择了宏内核下最务实的路径——模块级 undo 回滚：用 `RecoverableMutex` 在加锁时记录旧值，panic 时把域回滚到屏障点。它证明了单地址空间内做模块级恢复可行，也让"故障恢复"成了 QueenX 的一等子系统。

但"预览版"的三个问题把我们推向了重新思考：**恢复天花板**（固有 bug 的终态是整机宕机）、**undo 的尽力而为本质**、以及"**没有遏制，恢复就无根基**"。

### 目标的演进

最初的追求是"能恢复"；现在的追求是一组更强的组合：

- **MINIX 级安全能力**：服务故障不宕机，系统降级继续跑；
- **宏内核级性能**：热路径零运行时开销；
- **不依赖硬件**：纯软件实现；
- **子系统本身坚固**：恢复机制有界、可审计、可证明。

这组目标的核心认知跃迁是：**恢复不是主机制，遏制才是地基；恢复干净性必须由结构保证，而非恢复代码写得对。** 由此栏栈从"恢复型"演进为"遏制 + 重建型"。

### 原创主张：一个尚未被占住的组合

调研现有工作（MINIX 3、Singularity、RedLeaf、Theseus、CuriOS、Asterinas 等）后，我们确认以下组合在学术界仍是空白：

> **语言遏制 + 框架内核 + 不依赖硬件 + 微内核级故障重生 + 恢复范围可证封闭。**

这个组合蕴含三块原创性：

1. **理论主张（最硬）**：**恢复范围封闭**——遏制是编译期不变式，跨域状态互不可达 ⇒ 服务故障只可能损坏该服务自身状态 ⇒ 胶囊重建的恢复范围可证封闭。这把恢复从"尽力而为"升级为"有界保证"。
2. **机制组合（完整）**：undo 兜底 + 胶囊重建主路径 + BSR + BHR 仅 TCB 的系统性、可审计恢复子系统。
3. **故障消费纪律（最难）**：单地址空间内"域死亡 == 干净状态全清"的结构化并发设计。

成为真正"先河"的前提是三条都立得住：理论论证严谨、fault injection 实证恢复语义成立、性能数据证明宏内核级开销。

## 问题定义与现状诊断

### 现状：恢复型栏栈

栏栈当前是**恢复型**子系统：不做遏制，只做恢复。机制层在 `framework/barrier/`（`RecoveryDomain`、`UndoLog` 字节级回滚、屏障快照、BBR/BSR/BHR 分层恢复），策略层在 `services/barrier/`（`RecoveryPolicy` 决策矩阵、故障归属、健康监测、级联恢复）。

恢复的运作方式：域通过 `RecoverableMutex` 在加锁时把受保护值记入撤销日志（[recoverable.rs:60-73](src/kernel/framework/barrier/recoverable.rs)），后台 tick 推进屏障快照，panic 时定位域并级联回滚到目标代，恢复失败逐层升级 BBR → BSR → BHR（[layered.rs](src/kernel/framework/barrier/reset/layered.rs)）。

现状定位：这只是**预览版**。它证明了单地址空间内做模块级恢复可行，但没有遏制能力，安全性与 MINIX 级相去甚远。

### 恢复天花板：固有 bug 的终态是整机宕机

回滚只能吸收**瞬态故障**（竞态、时序、偶发输入）。若域存在**固有 bug**——同一代码路径每次必然复现——回滚后重跑必然再次 panic。此时机制的行为（[domain.rs:107-140](src/kernel/framework/barrier/domain.rs)）：

- 连续失败 ≥5 次 → 置 `Quarantined`，返回 false；
- 指纹判重：`prev_fp == crash_fingerprint` → 直接把 failures 置 5 → 置 `Quarantined`，返回 false。

指纹判重本是防崩溃循环的设计（对固有 bug，重试无意义且有 crash-loop 风险），但它的后果是：级联回滚找不到可回滚的域 → `recovery_try_recover_from_idt` 返回 -1（[api.rs:176](src/kernel/framework/barrier/api.rs)）→ IDT handler 触发 `kernel_panic("Domain recovery failed")`（[idt.rs:695](src/kernel/framework/idt/idt.rs)）→ BSR 失败 → BHR 键盘复位 / 三重故障（[bhr.rs:38-53](src/kernel/framework/barrier/reset/bhr.rs)），整机宕掉。

结论：**`Quarantined` 只阻止了"再尝试回滚"，没有消费这次 panic。** 一个服务域固有 bug 的终态不是"该域牺牲、系统降级继续跑"，而是整机宕机——这正是与 MINIX 的差距所在。

### undo 回滚的固有局限

- 只回滚注册过的字段（加锁时记录的旧值），未记录的状态与外部副作用（设备寄存器、IPC 副作用、已落盘数据）不可回滚；
- 回滚写回带校验和判断（[undo_log.rs:85-107](src/kernel/framework/barrier/undo_log.rs)），尽力而为，不保证语义一致；
- 恢复正确性依赖"恢复代码写得对"，属于**靠代码尽力**，而非**靠结构保证**。

## 实证调研：可变性分布与恢复覆盖率的真实缺口

"恢复范围封闭"要成为工程现实，先得回答一个诚实的问题：**当前代码里，到底有多少状态被 undo 日志覆盖？** 为回答它，我们对可变性做了两层审计——第一层数总量，第二层按"锁 vs 原子 vs 内部可变性"的交叉切面分类。结果直接改写了原始策略：**"全遏制"内部可变性既不可行，也不必要。**

### 第一层：可变性总量分布（services 层口径）

| 可变性形态 | 数量 | 分布 | 说明 |
|---|---|---|---|
| 原子类型使用点（`Atomic*`） | 610 | 53 文件 | 含 import 与字段；**静态原子全局 21 处** |
| 锁原语使用点（`IrqSpinLock`/`SpinLock`/`Mutex`/`RwLock`） | 425 | 61 文件 | 含 sync 模块自身定义；**静态锁容器 16 处** |
| 内部可变性载体（`Cell`/`RefCell`/`OnceCell`/`UnsafeCell`） | 84 | 36 文件 | services 仅 9 处，多为 `OnceCell`（写一次） |
| `static mut` 实际声明 | 0（services）/ 1（framework） | — | framework 1 处为 `smp_init` 的 `AP_PER_CPU`（TCB 启动期） |
| `RecoverableMutex` | 定义 1 处 / **使用 0 处** | — | 仅 framework 定义 + re-export |

计数口径：本次 grep 的 services 层全量匹配；`Cell<`/`RefCell<` 为子串匹配，含 `OnceCell`/`UnsafeCell` 等衍生类型。

### 第二层：三类结构性发现

**发现一：锁保护类型内的内部可变性（undo 覆盖漏洞候选）**

锁只保护"结构性元数据"（槽位、表项），值本身走无锁原子——这是性能刻意为之，但 undo 日志（加锁时记录旧值）**无法捕获这些原子写**：

- [sysctl.rs:112-121](src/kernel/services/config/sysctl.rs)：`SysctlEntry` 的 `AtomicI64/AtomicU64/AtomicBool` 在 `IrqSpinLock<[Option<...>; 32]>` 内，锁只管槽位分配，读写路径无锁；
- [iouring.rs:120-131](src/kernel/services/io/iouring.rs)：`RingBuffer<T>` 的 `head/tail: AtomicU32` 在 `IrqSpinLock` 内——SPSC 环形队列的头尾指针是**语义性无锁状态**；同文件 `IoUring.flags: AtomicU32` 同理。

**发现二：无锁共享状态（越出恢复范围候选）——21 处静态原子全局，分四类**

| 类别 | 实例 | 丢失 / 回退语义 |
|---|---|---|
| 栏栈自身恢复控制 | [reset_config.rs:108-114](src/kernel/services/barrier/reset_config.rs) 的 `CURRENT_LAYER`/`RESET_IN_PROGRESS`/`BBR/BSR/BHR_ATTEMPT_COUNT`/`LAST_RESET_TICK`/`PARALLEL_ROLLBACK_ACTIVE`（7 处） | 不能回滚——它们是回滚动作的输入 |
| ID / 统计计数器 | `NEXT_NS_ID`/`NEXT_URING_ID`/`NEXT_CGROUP_ID`/`FLOCK_OPS`/`POSIX_LOCK_OPS`（5 处） | 丢失可容忍（ID 用新值继续） |
| 生命周期标志 | `NET_READY`/`NET_CONFIGURED`/`CGROUP_INITIALIZED`（3 处） | 重建时重置为已知初值 |
| 语义性无锁状态 | [memory_pressure.rs:93-98](src/kernel/services/mm/memory_pressure.rs) 压力级 / 阈值（5 处）；`KASLR_BASE_OFFSET`（启动期定值） | 有协议保证，undo 会破坏其语义 |

**发现三（最关键）：`RecoverableMutex` 全内核无使用点。**

预览版 undo 回滚的注册覆盖率是 **0**——没有任何服务域的状态被登记进撤销日志。这意味着"恢复范围封闭"在当前代码里**不成立**：不是"记录不完整"，而是"根本没记录"。这是"预览版"最硬的一条实证：undo 机制存在，但从未接入真实业务状态。

### 策略修订：原子三级分类取代"全遏制"

"全遏制"（所有内部可变性都纳入 undo）**不可行且不必要**：

- **不可行**：发现一/二中的语义性无锁状态有明确无锁协议（SPSC 头尾、单写多读原子值），undo 回滚会破坏它们的语义；
- **不必要**：纯计数器丢失无害，生命周期标志 / 阈值在重建时可重置为初值。

唯一必须"遏制"的是 **C 类**——锁写路径上的普通字段（锁保护的 `&mut` 数据）。由此修订为三级分类策略：

| 级 | 类别 | 例 | 恢复归属 |
|---|---|---|---|
| A | 纯计数器 / 统计 | 尝试计数、锁操作统计、ID 分配器 | 不纳入恢复；回退 / 重置无害 |
| B | 语义性无锁状态 | SPSC `head/tail`、sysctl 原子值、压力阈值、生命周期标志、启动期定值 | 不纳入恢复；胶囊重建时重置为已知初值，语义由协议保证 |
| C | 锁写路径的普通字段 | 锁保护数据结构中的非原子字段 | **唯一纳入恢复的范围**：结构性强制（undo 注册 / 胶囊状态） |

### 栏栈自身状态：越出恢复范围的登记

`reset_config.rs` 的原子变量是栏栈**自身的恢复控制面**——它们是回滚动作的输入，若被回滚则自指（回滚动作自己需要被回滚）。处理方式不是"遏制"，而是**登记为越出恢复范围**：

- 语义被限制为简单原子 RMW（无复杂不变式），正确性靠构造保证；
- 作为控制面状态由 recovery 路径直接读写，生命周期与 TCB 一致；
- 对它们的破坏 = TCB 级故障 → BHR，与"TCB 受信任基座"的边界一致。

### 修订的恢复范围封闭定理

> 封闭对**锁写路径**成立（结构性强制：所有由锁保护的普通字段，其写路径都在胶囊重建 / undo 注册范围内）；对**已登记的越出恢复范围的无锁状态**（A/B 类 + 栏栈控制面）不提供恢复保证，但保证它们与恢复**隔离**——恢复不回滚它们，它们也不参与恢复正确性论证。

这把"恢复范围封闭"从一句口号，落成一条可审计的边界：**C 类写路径必须能证明封闭，A/B 类必须在登记表上，二者之间不允许第三类状态。**

### 推倒重来预案：必要时实现可从零重建

预览版的存在不等于新架构必须兼容它。**已定决策：在必要情况下，栏栈实现允许推倒重来**——现有代码（`RecoveryDomain` / `UndoLog` 字节级回滚 / `RecoverableMutex` / 分层恢复）是"预览版"的证明性实现，不是约束。

- **触发条件（必要情况）**：旧实现与目标架构冲突，且改造面 ≥ 重建面。具体：若 C 类锁写路径的类型强制、胶囊重建、结构化并发所需的原语无法在旧实现上自然生长（旧接口绑定了 undo 世界观），则推倒重来。
- **判定口径**：**结构保证 > 代码复用**。能证明"恢复范围封闭"的形态优先于保留旧代码；复用旧代码若削弱结构性保证，则不复用。
- **保留清单**（推倒重来不丢的）：理论主张（封闭定理）、已定决策（方案 A、三级分类、两条腿、TCB 受信任基座）、检测与策略理念（BBR/BSR/BHR 分层、健康监测、故障归属）——可移植、可保留。
- **丢弃清单**：以 undo 为中心的机制本体（`RecoverableMutex` 注册、`UndoLog` 字节回滚）——若与胶囊重建的结构性强制冲突；已被审计证明 0 覆盖率的设施没有兼容义务。
- **推倒重来的边界**：TCB 边界不变；framework 不可因栏栈重建而扩大 unsafe 面；services 层 0 unsafe、F1-F9 硬规则不变。

## 设计目标与边界

### 目标

对标 MINIX 微内核的安全能力：**服务域故障不导致整机宕机**，而是"该域牺牲/降级、系统其余部分继续运行"，同时满足：

- **保证性能**：热路径零运行时开销；
- **不依赖特殊硬件**：路径 1 纯软件（不使用 MMU / PKU / MTE 等硬件隔离）；路径 2 仅依赖现代多核处理器普遍具备的标准能力（多核 / 每核 MMU / SMP / cache coherent），不依赖专属硬件（见"架构形态：Isolated 独立空间裁决核心"章）；
- **子系统本身坚固**：恢复机制自身有界、可审计、可证明。

### 诚实边界：TCB 是受信任基座

纯软件遏制无法约束 framework 的 unsafe 代码——TCB 内存一旦损坏，恢复机制本身运行在已损坏的内存上，不可信。因此软件隔离只作用于 services 层；framework（TCB）是**受信任基座**，TCB bug → BHR 是可接受的终态。

这与 MINIX 一致：MINIX 的微内核同样受信任，其安全来自"内核之外的一切被隔离且可重启"。对应到 QueenX：**TCB（framework）受信任 + services 软件隔离**，而非把整个内核都塞进软件遏制。

## 理论基础：两个先例与机制替代

### MINIX 进程重生

MINIX 的机制是**进程重生**：MMU 强制地址空间隔离（遏制）；进程死亡时内核拆除其地址空间、线程、栈、锁、IPC 端点（**状态与执行上下文全清**）；Reincarnation Server 重启驱动。

关键：一个机制（进程 + MMU）同时解决遏制与重启，干净性由硬件结构保证，无需恢复代码"写得对"。

### Singularity OS

Microsoft Research 的单地址空间 OS：不依赖 MMU，用类型安全语言（Sing#）做隔离——软件隔离进程（SIP）+ 类型化信道通信 + 系统验证器。

它证明了**"纯软件隔离"在理论上成立**：隔离可以由编译器强制，而非硬件。Singularity 最终未成为产品（性能与实用性的教训），但作为设计先例，其"语言强制隔离 + 显式通信"正是本设计的原型。

### 机制替代

| MINIX 靠硬件做到 | 纯软件替代 | 代价 |
|---|---|---|
| 遏制：MMU 隔离地址空间 | 所有权 / 类型系统强制：services 100% safe Rust + 跨域零共享可变状态 | 编译期不变式，**零运行时开销** |
| 重启：进程拆除 | 域胶囊 drop + 重建（RAII） | 逐域改造 |
| 通信：IPC 过内核 | 内核内显式消息传递（无硬件切换） | 低于真微内核 |
| 检测：硬件异常 | 软件看门狗 / CPU 配额 / 心跳 / 不变式断言 | 需服务层配合 |

### 核心命题

- **遏制 = 编译期不变式**。MMU 在运行时拦截越界；所有权在编译期就保证不越界。前者有硬件开销，后者零开销——这是"保证性能"的答案。
- **重启干净性 = 结构保证**。Rust 语义保证 drop glue 递归执行；若域状态只通过胶囊可达（无逃逸引用），则胶囊 drop 即**状态总回收**——等价于 MMU 回收地址空间，只是把"硬件强制"换成"类型系统强制"。

> **决策修订（后续推演）**："Drop 即总回收"已被 **create 即总回收** 取代——`no_std` panic=abort 语境下 Drop 在故障现场不可靠（析构可能再拿锁 / 嵌套 panic / 依赖已破坏的不变式）。恢复的最终动作改为"清零整块 capsule buffer + 重调 `Domain::new()`"，不跑任何 Drop。遏制命题不受影响，仍然成立。详见"全 create 化恢复模型"章。

## Rust 特性利用：把遏制 / 回收 / 故障变成语言保证

Rust 支撑本设计的关键，在于它把"遏制、回收、故障"三件事从**运行时机制**变成**编译期或结构保证**。逐条映射到设计支柱。

### 遏制（语义隔离）：编译期不变式

| 特性 | 用法 | 落到设计哪里 |
|---|---|---|
| **所有权 + 移动语义** | 一个值只有一个拥有者；转移所有权零成本 | 胶囊状态唯一拥有权；域间传数据用 move（转移）而非共享 |
| **借用检查（`&mut` 独占 / `&` 共享不可变）** | 编译期禁止跨域共享可变状态 | "遏制 = 编译期不变式"的直接实现者——域 A 若持域 B 状态的可变借用，编译器就拒绝 B 同时触碰 |
| **模块可见性（`pub` / 私有）** | 私有字段不可命名、不可触碰 | 域内部状态对域外不可见 |
| **`Send` / `Sync` auto traits** | 编译器判定值能否跨线程转移 / 共享 | 跨域共享的编译器门禁——胶囊内部类型标 `!Sync`，编译器强制无人能共享它 |
| **内部可变性（`Cell` / `RefCell` / `Mutex`）** | 借用的"逃生门"，运行时检查 | 域内部可自由用；域边界必须禁用，由 API 设计 + 审计强制 |

### 胶囊重建（总回收）：确定性析构

| 特性 | 用法 | 落到设计哪里 |
|---|---|---|
| **`Drop` / RAII** | 作用域结束确定性销毁，无 GC | 胶囊 drop = 递归销毁全部 owned 状态——"状态总回收"的机制本体 |
| **移动语义** | 谁拥有谁析构 | 域状态只通过胶囊可达 ⇒ drop 即总清（无逃逸引用） |
| **析构顺序（字段序 / 自定义 `Drop`）** | 控制清理协议 | 胶囊析构时的外部资源释放（设备句柄、页、fd） |

### 故障消费：panic + 错误传播

| 特性 | 用法 | 落到设计哪里 |
|---|---|---|
| **`panic`（内核通常 `panic=abort`）** | 域内 panic = "我坏了"的故障信号 | 现有栏栈正是这么接的（IDT 路径）；把 abort 改造成"胶囊重建入口"：panic handler → 栏栈 → drop 胶囊 → 重建 |
| **`Result<T,E>` + `?`** | 错误沿调用栈显式传播 | 域死亡的消费者——调用方拿到 `Err` 而非 kernel panic；域边界的返回类型即故障契约 |
| **线程模型 + `Send`** | 线程对象可被拥有 / 转移 | 域拥有 worker 线程 ⇒ 线程 drop ⇒ 栈回收（故障消费的地基） |

### 域间通信与性能

| 特性 | 用法 | 落到设计哪里 |
|---|---|---|
| **移动语义（零拷贝转移）** | 传数据 = 转移所有权，非复制 | 内核内 IPC 的零拷贝方案 |
| **`trait` 接口（含 trait object）** | 把域边界协议形式化为接口 | 胶囊接口 = trait；调用点只依赖 trait 而非内部实现 |
| **泛型 + 静态分发** | 编译期单态化，无虚表 | 热路径零运行时开销的直接答案 |
| **`Arc` / `Weak`** | 只读共享所有权 | 跨域共享只读数据（如配置）时可用——但需纪律：共享可变 / 引用计数会破坏"总回收"，是语义隔离的缺口 |

### 纪律与审计（让上述保证可维护）

| 特性 | 用法 |
|---|---|
| **`unsafe` 的封装性** | 只允许 framework 用 unsafe 并封装为 safe API；TCB 边界本身就是遏制边界 |
| **宏 / derive** | 把"域边界纪律"声明式化（自动生成胶囊骨架、IPC 协议），减少手写错误 |
| **`cfg` 条件编译** | fault injection / 测试钩子（项目已有 `kernel_test` / `fault_injection` feature） |
| **typestate / PhantomData（类型状态）** | 编码胶囊生命周期状态机（Running → Faulted → Rebuilt），非法转移在编译期拒绝 |

### 三个关键杠杆

1. **所有权 + 借用**：把"遏制 = 编译期不变式"从口号变成编译器强制——这是"恢复范围封闭"理论能成立的语言学基础。
2. **`Drop`**：把"重启干净性 = 结构保证"变成确定性语义——胶囊 drop 即总回收。
3. **`panic` + `Result`**：把"故障消费"变成可表达的协议——panic 是自杀信号，`Result` 是死亡通知。

### 诚实的边界

- **内部可变性、`Arc`、`unsafe`** 是三个破坏上述保证的逃生门，不能消灭，只能**用纪律约束**（API 边界 + 审计脚本）。
- **unwind vs abort**：`no_std` 内核默认 abort，无法用 `catch_unwind` 优雅吞掉 panic——所以"域死亡"必须走**胶囊重建**路径（abort 信号 → 栏栈接管）。这是本设计与用户态 try/catch 思路的分水岭。

## 两条腿：胶囊重建（主）与 undo 回滚（兜底）

- **主路径 = 胶囊重建**：结构保证的干净重启，对标 MINIX 进程重生。
- **兜底 = undo 回滚**：只吸收瞬态故障的安全网，靠代码尽力。

undo 成不了主机制的原因：外部副作用不可回滚、恢复范围依赖记录覆盖、恢复正确性不可证明。因此分层恢复中，回滚只做瞬态兜底，固有 bug 走胶囊重建，BHR 只保留给 TCB。

> **决策修订（后续推演）**：全 create 化定型后，undo 的"兜底"地位也被取消——`UndoLog` / `RecoverableMutex` / `DomainState<T>` 强制注册一系机制整体退出目标架构，恢复收敛为**单主路径**（裁决 → create 化重建）。命门①"undo 注册的类型系统强制"随之关闭：不再需要证明"哪些写被登记"，只需要划对"哪块 buffer 属于该域"。三级分类的作用从"定义 undo 覆盖"收敛为"定义 buffer 边界与跨域存活状态的登记"。undo 预览版仅保留为可行性证据。

## 四个深层子问题

### 语义隔离

"内存安全"（safe Rust 已保证不越界）与**语义隔离**（一个域的 bug 连语义上都碰不到另一个域的状态）是两回事。后者要求**跨域零共享可变状态**、全部显式通信。

语义隔离是恢复封闭性的前提——只有跨域状态互不可达，"胶囊重建只重建该域状态"才是可证明的。

### 故障消费

单地址空间里"杀死一个域的线程"：栈回收、锁所有权、被阻塞调用方唤醒。MINIX 靠进程拆除免费获得；单地址空间需显式设计（结构化并发）。若不做故障消费，panic 冒泡 → BHR——正是当前现状。

### 无硬件检测

- 死循环 → 软件看门狗 / 抢占超时；
- CPU 占用 → 配额（现有 `cpu_quota_max` / `check_quota`，[domain.rs:286-296](src/kernel/framework/barrier/domain.rs)）；
- 心跳（现有 `heartbeat_max_gap` / `check_health`，[domain.rs:302-313](src/kernel/framework/barrier/domain.rs)）；
- 不变式断言（I1-I6，见 [explain-framekernel.md](./explain-framekernel.md)）。

检测精度低于硬件，但服务层可用。

### 恢复正确性论证

因为遏制是编译期不变式，"服务故障只可能损坏该服务自身状态"**可证明** → 胶囊重建的恢复范围**封闭**。这把恢复从"尽力而为"升级为"有界保证"。

封闭的工程边界由实证调研钉死（见"实证调研"章）：封闭对**锁写路径**成立（C 类结构性强制）；对**已登记的越出恢复范围的无锁状态**（A/B 类 + 栏栈控制面）只保证隔离、不保证恢复。任何既不在 C 类写路径、又不在登记表上的状态，都是封闭性缺口，须在设计中消除或登记。

## 架构形态：域 = 胶囊

域 = **所有权作用域（胶囊）+ 显式 IPC**。域拥有状态（数据结构）；执行回收的**理论终态是方案 A（完整胶囊）**——域同时拥有线程组，经协作取消（安全点）+ 栈回收完成执行流回收（见下"域边界模型"）。

分层恢复形态：

```text
L0 遏制（所有权/类型系统）        ← 本设计的根本，编译期不变式
L1 就地回滚（undo，瞬态兜底）      ← 现有栏栈能力
L2 胶囊重建（固有 bug 主路径）      ← 结构保证的干净重启
L3 BSR（设备软重置）              ← 现有能力
L4 BHR（仅 TCB）                 ← 受信任基座故障才允许整机宕机
```

### 域边界模型：执行回收的终态是方案 A

"域是否拥有线程"是执行回收的分叉点。所有权只保证**状态总回收**，不保证**执行总回收**——在共享地址空间里中止一个正在跑的线程是硬问题。谱系：

| 方案 | 形态 | 故障时执行流处理 | 改造面 |
|---|---|---|---|
| B 半胶囊 | 域只拥有状态，线程归调度器 | RCU 式排空（grace period） | 最小 |
| B+ 域 worker 池 | 域拥有固定 worker 池 | 整池重建 + 有界泄漏 | 中 |
| **A 完整胶囊（终态）** | 域拥有状态 + 线程组 | 协作取消（安全点）+ 栈回收 | 最大 |

**已定决策：第一条路径（纯软件一体式栏栈）的理论终态 = A。** 含义：

- **定义**：域胶囊拥有「状态 + 线程组」；故障时经协作取消（安全点）+ 栈回收完成执行流回收，向 MINIX 进程模型对齐。
- **地基**：crash-only 段纪律——安全点之间的代码段只动域局部状态，这是"中止线程是否安全"的前提。
- **实施路线（已记：方案之一 = 形态 A + 推倒重来）**：面向 A 设计；施工上允许推倒重来——弃旧 undo 预览版（`RecoverableMutex` / `UndoLog`），直接引入新的受控锁原语（`DomainState<T>`）与胶囊原语，不背兼容包袱（见"推倒重来预案"）。B/B+ 不作为默认路线，仅作渐进验证台阶。
- **分工边界**：A 管"域怎么死"；Isolated（独立空间裁决核心，另章讨论）管"谁裁决 + 谁能强制复位"，两者正交。

**诚实的上限**：A 是纯软件共享地址空间内执行回收的极限表达；它只解决"共享空间内的执行回收"，不解决"任意时刻拆除执行流 + TCB 故障也能裁决"——后者是 Isolated 路径（第二条路）的地盘。

域粒度、与现有 `RecoveryDomain`（恢复域）的关系均为开放议题（undo 注册 API 的可证强制已由命门①决策承接，见下）。

### 命门决策：两条工程命门选"是"

方案 A 能否成立，取决于两条工程命门——它们收敛为同一决策：是否引入**受控锁原语**。已定决策：**两条命门均选"是"**，并绑定"形态 A + 推倒重来"的实施路线。

**命门①：undo 注册的类型系统强制 → 是。** 由受控锁原语 `DomainState<T>` 承担——对 C 类锁写路径强制 undo 注册（加锁即登记旧值），使"恢复范围封闭"在工程上可证。A/B 类无锁状态走登记豁免，不纳入恢复（见"实证调研"章三级分类）。

**命门②：crash-only 段的强制方式 → 是。** 以结构强制为主：作用域 / typestate 让跨安全点的跨域引用在编译期非法，审计脚本兜底。随方案 A 的胶囊原语一并设计，不单独前置。

实现载体与推倒重来一致：弃旧 `RecoverableMutex`，在干净地面引入 `DomainState<T>` 受控锁原语与胶囊原语。两条命门选"是"的代价已由审计钉死——undo 覆盖率为 0（无迁移包袱）+ 三级分类收窄范围（仅 C 类需强制）——使"是"从口号变为有界、可落地的工程决定。

### BCB：栏栈全局控制块（全局唯一）

BCB（Barrier Control Block）是栏栈的**全局唯一控制中枢**——类比内核的进程表 / TCB 目录：一个结构承载栏栈对全系统域的完整控制视图，替代散落各处的域元数据与栏栈控制面。

**动机**：路径 1（胶囊模型）与路径 2（Isolated 仲裁）都需要"对每个域看全、看一致"，而现状要跨 framework 层（`RecoveryDomain` / `RecoveryManager`）与策略层（`FaultAttribution` / `DomainTopology` / `HealthMonitor`）多个结构拼接。BCB 提供统一的**域控制事实源**，两条路径共享同一份元数据视图。

**职责边界**：BCB 只做**控制面**（元数据）；域的实际业务状态在**胶囊**（数据面，RAII drop 总回收）。类比：TCB 只含线程元数据，不含线程栈。这条分离是 BCB 不膨胀、不引入热路径开销的前提。

#### 功能区与内容（五区）

| 区 | 内容 | 落位 / 替代 |
|---|---|---|
| ① 全局身份与版本 | `magic` / `version`（防误用、防布局漂移）；工作模式 `mode`（Path1 / Path2 / Degraded，决定仲裁语义与能力适配档） | 新建 |
| ② 栏栈控制面 | `current_layer` / `reset_in_progress` / `bbr/bsr/bhr_attempt_count` / `last_reset_tick` / `parallel_rollback_active` / 全局健康水位 | 归位 [reset_config.rs:108-114](src/kernel/services/barrier/reset_config.rs) 散落原子 |
| ③ 域注册表 | 域槽位数组 + 空闲位图 + 查找索引；每域 `DomainEntry`（状态机 / 代 / 配额 / 心跳 / 恢复等级 / 是否 TCB 边界标记）；拓扑依赖 | 替代 `RecoveryManager` + `RecoveryDomain` 控制面部分 |
| ④ 恢复范围登记表 | 每域三级分类 A/B/C 归属；已登记的无锁共享状态清单（A/B 类）；越出恢复范围的栏栈自身状态标记；胶囊重建现场（重建语义 / 重置函数指针） | 三级分类与封闭定理的**工程落点** |
| ⑤ 仲裁现场 | 现场快照入口（Inline 层维护、Isolated 层只读）；裁定结果 / 复位裁定历史 | 服务路径 2 的仲裁输入 |

#### 域注册表 vs 域目录（命名决策）

命名承载设计承诺：

- **目录 Directory** = 固定槽位的预分配实体，无生命周期，查不到就是没有——与现有 `RecoveryDomain` 静态预分配一致，但**与胶囊模型冲突**（胶囊的核心是域的创建 / 重建 / 销毁）；
- **注册表 Registry** = 有生命周期的成员（`register` / `unregister` / `iter`）——贴合路径 1 方案 A 的胶囊重建语义，且与④"恢复范围**登记**表"用词同源（同是 register 语义），与路径 2 的成员遍历（仲裁需列出所有域现场）兼容。

**已定：域注册表 DomainRegistry**。语义上是注册表（对外生命周期接口），物理上是目录（固定槽位 + 空闲位图，保留 O(1) 查找与紧凑性，不引入链表遍历开销）：

```rust
pub struct DomainRegistry {
    // 物理：固定槽位 + 空闲位图（目录形态，O(1) 查找）
    slots: [Option<DomainEntry>; MAX_DOMAINS],
    free_bitmap: AtomicU64,
    // 语义：register() / unregister() / iter() 生命周期接口（对外呈现注册表）
}
```

#### 并发与性能

- **全局唯一但不全局锁**：每域槽位独立锁 / 原子 + 目录元数据单独锁（读路径近似 RCU 无锁）；
- **热路径不碰 BCB**——服务调用走胶囊（数据面），BCB 只在登记 / 健康采样 / 故障仲裁时访问，避免 BCB 成为锁竞争点。

#### 初步骨架

#### 单点风险（可接受终态）

BCB 是栏栈控制面的单点——被破坏 = TCB 级故障 → BHR。这与既有"栏栈控制面越出恢复范围、破坏即 TCB 级"的边界一致（见"实证调研"章），不引入新的信任缺口。

## 架构形态：Isolated 独立空间裁决核心（第二条路径）

### 定位：回答路径 1 的两个上限

路径 1（域 = 胶囊）是纯软件共享地址空间内执行回收的极限表达，但它有两个诚实的上限：

- **任意时刻拆除执行流**：协作取消依赖安全点，被取消的线程必须恰好停在安全点；共享地址空间里"强制中止一个正在跑的线程"没有硬件背书；
- **TCB 故障也能裁决**：路径 1 的裁决者（栏栈自身）与故障域同处一个地址空间，若 TCB 内存损坏，裁决本身不可信。

第二条路径用**独立空间裁决核心**（Isolated）回答这两个上限：把"谁裁决 + 谁能强制复位"从故障发生的地址空间中挪出去，放在一个隔离的裁决环境（独立地址空间；执行手段见"隔离手段光谱"）。

分工边界：**A 管"域怎么死"；Isolated 管"谁裁决 + 谁能强制复位"**。两者正交——路径 1 负责域内的干净回收语义，路径 2 负责域外的仲裁权威与强制力。

**半单地址空间定位**：路径 2 处于单地址空间（路径 1）与全多地址空间（MINIX）之间——**主体服务间仍单地址空间**（软件遏制，热路径零开销），**只有裁决核心那一半独立出去**（隔离地址空间）。隔离是**非对称**的：服务与服务的遏制靠语言（编译期、零成本），裁决者对服务的隔离靠硬件（最强、冷路径）。对应性能：**热路径比 MINIX 更快**（无特权级/地址空间切换），**冷路径安全效果比肩 MINIX**（仲裁权威性相当，且裁决环境不参与服务运行、不被故障域拖累）。

### 双层结构

第二条路径是双层栏栈：

| 层 | 位置 | 职责 | 路径 |
|---|---|---|---|
| Inline 层 | 与内核同地址空间 | 热路径：undo 日志、屏障快照、健康监测采样 | 每次服务调用都经过，须零 / 极低开销 |
| Isolated 层 | 专用核，独立地址空间 | 冷路径：故障仲裁、裁决是否重建、强制复位 | 仅故障时进入，开销不敏感 |

Inline 层不引入额外隔离，保持宏内核热路径的性能形态；Isolated 层用独立地址空间把裁决核心与故障域隔开——故障即使击穿 Inline 层的一切遏制，也无法直接污染裁决者。

### 硬件依赖论证

Isolated 层依赖的是**现代多核处理器普遍具备的标准能力**，而非特殊硬件：

- **多核**：存在至少一个可被指派的专用核（实际执行环境普遍 ≥2 核）；
- **每核 MMU**：每个核有独立页表，可给 Isolated 核分配独立地址空间；
- **SMP + cache coherent**：核间状态可见、可同步，裁决者可读取被隔离核的现场。

跨架构支持：

| 架构 | 支撑能力 | 说明 |
|---|---|---|
| x86_64 | 多核 + 每核 CR3 页表 | 通用 |
| aarch64 | 多核 + TTBR0/1 + ASID | 通用 |
| RISC-V | 多核 + SATP + SBI + PMP | **最优**：SBI 提供核间管理与复位接口，PMP 可作物理内存隔离的又一重保障 |
| LoongArch | 多核 + 每核页表 | 通用 |

与路径 1"不依赖硬件"的关系：路径 1 不依赖任何硬件隔离机制（单核也能结构隔离）；路径 2 也**不依赖特殊硬件**——它只把"多核 + 每核 MMU"这些标准能力用作裁决者的隔离手段，而非依赖专属加速特性。二者共享"不依赖特殊硬件"的立场，区别在于路径 2 需要多核才能获得真隔离。

### 隔离手段光谱：消除"扣核"尴尬的三个档位

"裁决者必须在故障域之外"有三种硬隔离手段，专用核只是其一。三者构成**三角张力**：**不扣核 ∧ 效果一致（隔离裁决者）∧ 不依赖硬件扩展，只能取其二**。

| 档位 | 隔离本质 | 硬件依赖 | 扣核 | 适用 |
|---|---|---|---|---|
| **按需借核（主推）** | 空间隔离（独立地址空间按需映射） | 多核 + 每核页表（标准） | 仅事件时瞬时 | 所有多核设备 |
| 专用核 | 空间隔离（常驻独立地址空间） | 多核 + 每核 MMU（标准） | 持续 1 核 | 有富余核设备 |
| 特权层守护 | 特权隔离（HYP / EL3 / HS） | 虚拟化/安全特权扩展 | 无 | 有安全扩展设备（不限核数，单核可用） |

**按需借核（任何核皆可借）**是消除"专用核扣一颗大脑且平时不干活"尴尬的主推方案：

- **平时**：所有核自由运行任务，零扣核；冷路径栏栈驻守独立地址空间，且**该空间平时在所有核的页表中不映射**——任何代码（含故障 TCB）物理上不可达；
- **事件时**：事件源（硬件异常 / NMI / FIQ / 看门狗，现代平台标配）投递到任意核 → 该核"变身"裁决核（保存上下文 → 注入冷路径空间映射 / 切换页表 → 执行裁决）；
- **结束后**：撤销映射、恢复原上下文，核归还。

配套机制（四件）：① **事件源 = 标配硬件**（见下）；② **最小切换代码**：每核只读段静态存在，TCB 级信任（保存上下文 + 切页表 + 跳转，极小）；③ **短暂扣核的锁纪律**：裁决逻辑不能依赖被挂起任务的锁状态（被变身核原任务被挂起微秒级）；④ **并发变身协议**：多事件同时到达需"主导-协作"仲裁。

**事件源硬件确认**（现代平台标配，非特殊硬件）：

| 架构 | 事件源 |
|---|---|
| x86_64 | NMI（LINT1）、APIC、Machine Check、watchdog |
| aarch64 | FIQ（GIC）、SError/SEA、generic timer、watchdog |
| RISC-V | NMI / SBI、PLIC/CLINT、IPI、watchdog |
| LoongArch | NMI、IPI、watchdog |

这些均属"现代处理器标配能力"，不依赖 SGX / TrustZone / 专属加速器等特殊硬件；RISC-V 若缺 NMI 可降级用 IPI + 最高优先级 IRQ。

### 能力适配

按硬件配置选档：

- **有安全特权扩展**（虚拟化 / EL3 / HS，不限核数）→ 特权层守护（最优雅，不扣核，**单核也可用**）；
- **无扩展 + 多核** → 按需借核（主推，不常驻扣核）；
- **无扩展 + 有富余核且接受扣 1 核** → 专用核档；
- **无扩展 + 单核** → 按"是否存在不可屏蔽中断"分叉：x86_64 / aarch64 的 NMI / FIQ **软件关不掉**（IF=0 拦不住），watchdog 事件照样能打开场——同核原地裁决（NMI handler 变身 → 裁决 → create 化 → 改写中断返回帧重定向到新入口），外科式恢复仍成立，代价是全系统冻结几十 μs；只有连 NMI 也缺失 / 可屏蔽的 RISC-V 低端单核 MCU，才落到"裁决者无入场机会、看门狗硬复位"——那已是硬件能力下界，任何软件方案（含 MINIX）在此都只能复位。

任一配置下都有确定的恢复语义，只是隔离强度、扣核形态与恢复粒度不同。

### 架构抽象

Isolated 层所需的架构差异（专用核指派、地址空间切换、核间同步、复位）收敛到一个**窄架构抽象层**，复用现有 `arch!` 宏系统——把每架构不同的 3~5 个原语（如 `allocate_isolated_core`、`switch_isolated_address_space`、`signal_isolated_core`、`reset_isolated_core`）作为宏分支，其余仲裁逻辑架构无关、用纯 Rust 单份实现。仲裁逻辑本体保持单份，跨架构只换薄薄的适配面。

## 无条件执裁：裁决者不依赖"故障代码写没写对"

MINIX 对本设计的根本诘难是：MMU 不管你的代码写没写对，越界就是硬件拦截；栏栈能否做到"不管代码写没写对，都能执裁"？答案分两层。

**遏制层：对 services 而言，100% safe Rust 不比 MMU 弱，甚至更强。**

| 破坏性操作 | MINIX / MMU | services 0 unsafe（编译器） |
|---|---|---|
| 越界读写 | 运行时 page fault 拦截 | 编译期拒绝，该代码不存在 |
| use-after-free | MMU + 引用计数 | 所有权系统编译期拒绝 |
| 数据竞态 | 进程隔离 + IPC 串行化 | Send/Sync + `&mut` 独占，编译期拒绝 |
| 触碰裁决者内存 | ring 特权级不可达 | 裁决者字段跨 crate 不可见、不可命名、不可调用 |

MMU 的保证是"你写错了运行时拦你"，Rust safe 代码的保证是"你写错了根本编译不出来"。对"services 代码写没写对"这个命题，编译期不变式是严格更强的断言。**所以执裁不需要假设故障域配合**——其破坏力在编译期已被消灭。

**执裁层：残余的两个依赖，以及各自的消解方式。**

1. **裁决者自身不能有 bug** → 以"小到不可能错"消解：裁决状态机独立 crate 化（见下章），<500 行、`forbid(unsafe_code)`、零依赖，人工可穷尽审查。MINIX 敢信任它的 6K 行微内核，理由同构——不是魔法，是小；
2. **恢复不能执行故障代码** → 以全 create 化消解（见再下章）：不跑 Drop、不 undo，裁决者的全部动作是"清零一块 buffer + 调一次 new() + 原子改代"。

两个消解完成后，栏栈执裁的依赖集收敛为：**编译器 + 硬件 + 一个 <500 行状态机**——与 MINIX 的"硬件 + 微内核"假设数相同。真正的差距从来不在"services 代码对不对"（编译器管了），而在"裁决者自己够不够小"——这一点由 crate 化 + 极小化自己掌控，不依赖任何外部资源。

## 裁决核心独立 Crate：第三个信任域

裁决者剥离后，栏栈形成三 crate 分工：

```text
src/kernel/
├── arbiter/          ← 独立 crate：裁决状态机（<500 行，零依赖）
├── framework/        ← TCB：BCB、Inline 快照、buffer 池、变身入口、判决执行
└── services/         ← 策略层：健康判定规则、故障归属、级联（0 unsafe）
```

依赖方向单一：`framework → arbiter`（framework 调用裁决函数并执行判决）；arbiter 不知道 framework 的存在——它的输入只是几个原子值快照（`ArbiterView`），输出只是一个 `Verdict` 枚举。裁决是纯函数：无锁、无分配、无副作用、步数有界，不可能死锁、不可能 panic。

crate 边界提供而模块边界做不到的三件事：

| 性质 | 强制机制 | 意义 |
|---|---|---|
| 对 framework 零依赖 | `arbiter/Cargo.toml` 的 `[dependencies]` 为空 | 编译器物理禁止 `use framework::...`，裁决者不可能误碰 139K 行 TCB 代码 |
| 无 unsafe | crate 级 `#![forbid(unsafe_code)]` | 由编译器证明，而非由审计脚本检查 |
| 可验证 | 单 crate 500 行边界 | Kani / 模型检验可穷举全部路径；任何人 30 分钟从头看完 |

**不拆的**：BCB / 注册表 / Inline 快照 / buffer 池留在 framework（要碰页表与硬件，必须 unsafe）；策略层留在 services（编译器已保护）。crate 化只切"做最终判决"这一最小单元——切的是信任链上需要独立自证的那一环，不是工程模块的整洁。

## 全 create 化恢复模型

**已定决策：放弃修复式恢复（undo / Drop），恢复语义收敛为"整块清零 + 重新 create"。**

```text
rebuild(id):                          ← framework 执行；arbiter 只给 Verdict::Rebuild
    memset(CAPSULE_POOL[id], 0)       ← 静态 buffer 池，零分配
    fresh = (registry[id].init_fn)()  ← 唯一入口 Domain::new()，跨 crate 类型不透明性强制
    bcb_release_external(id)          ← 代管资源（fd / slot）批量回收，不等域 Drop
    registry[id].gen.fetch_add(1)     ← 原子改代；这一刻 = 所有旧引用失效的时刻
```

四个支柱性质：

- **恢复范围不再需要论证**。恢复边界 = buffer 边界，由 framework 静态分配时划定，不由代码行为决定。封闭定理的工程形态从"强制 C 类写路径登记"升级为更简单的结构——**整个 capsule 就是恢复单位**，不存在"漏登记"这个概念。
- **不跑 Drop**（abort without unwind）。故障域的析构器永不在裁决上下文执行，panic=abort 下的 Drop soundness 难题被移除出关键路径。
- **拉取式失效 + Handle+Gen**。裁决者 gen++ 后不通知任何消费者。跨域引用一律值语义 `Handle { id, gen }`（禁裸指针与长生命周期引用），消费者经 framework lookup 时检查 gen，不匹配返回 `Err(Recovered)`——safe Rust 的 match 穷尽性把"处理域重建"变成编译期义务，想漏都漏不掉。失效传播是惰性、按需、强制的，这是"拉取式"相对"推送式回调"的核心优势：裁决者不需要知道谁在引用故障域。
- **外部资源代管**。域不向外申请可变资源；fd 表、socket buffer 等由 framework 经 BCB 代管，生命周期归 BCB 不归域 Drop，create 后可批量回收。

## 副作用一致性：三通道与设计规则（初步解）

对"整块清零 + 重新 create"的第一个严肃反驳是**数据错位**：胶囊的记忆回到了初始态，但外部世界已经前进了——已发送/接收的网络包、已写入磁盘的数据都不会跟着 gen++ 回滚。本节是初步研讨得到的解，有待 fault-injection 实证检验。基本立场先立住：

> **重建不解决数据错位，任何内核内恢复机制都不解决。全 create 化的进步不在于消灭错位，而在于不假装能消灭错位——把错位显式地关进三条各有标准解药的通道。undo 流派的问题恰是"日志回滚不了副作用"却暗示自己能回滚。**

### 三个通道分别算账

| 通道 | 错位形态 | 解药 | 栏栈承诺 |
|---|---|---|---|
| 已发送（不可逆） | 对端收到重复/半截交互；本端连接态随胶囊死亡 | 对端视角"胶囊重生 ≡ 网络分区"：超时重传、seq 去重、应用层重连——分布式协议的日常业务 | 不承诺 exactly-once，只承诺"故障表现归入协议已训练的等价类" |
| 已接收（真窗口） | 包已从硬件环取走、处理了、结果只存胶囊内存 → 重生即丢 | DMA 环 / RX 队列在 framework 代管区**跨代存活**，新胶囊从 head/tail 当前值继续排空；"取走未下沉"窗口用延迟消费语义压到单事务原子性尺度 | 已到达未处理不丢；丢的窗口有界且等于正常并发问题量级 |
| 已落盘（可判定） | journal 半提交 / torn write / 在途块请求 | 磁盘状态机本来就有标准答案：FS 域的 new() 就是 mount + journal replay（重放已提交 / 丢弃未提交 / checksum 检出 torn 页）；在途 IO 靠第二拍设备 reset + 超时重试 | 落盘一致性由日志层担保，与不崩溃系统同构 |

不可幂等的对外动作（控制命令、执行器指令）内核救不了，只能靠应用层幂等键/序列号——这是 End-to-End 论证的教科书案例，不是栏栈的缺陷，是分布式的物理事实。

### 设计规则：R1 落点分层 与 R5 完备性检验

> **R1（落点分层原则）**：已被外部世界确认的数据，其落点不得住在可重生的胶囊里。胶囊准入标准：**只住可再生的派生态**（缓存、索引、状态机）；权威账本住跨代存活层（journal / 硬件环 / BCB 代管区）。

> **R5（new() 完备性检验）**：若 `Domain::new()` 不能只从"持久层 + 跨代账本 + 硬件环 + 对端协议"重建出语义有效的运行态，则该域与外部世界的边界就划错了——它把不该住进胶囊的东西（账本）住进去了。审计一个域，只看它 new() 的输入来源清单：来源全是跨代层 → 错位免疫；缺了一块内存态 → 那块内存就是下一个 bug。

两条规则合起来，把"数据错位怎么办"从无穷发散问题收敛为**可检查的设计约束**：错位窗口不再靠枚举场景堵漏，而是被 R1 的边界划定直接排除在恢复范围之外。

### 与 MINIX 的持平声明

发送侧连接死亡、接收侧环形缓冲存活、磁盘侧 journal 重放——三通道上栏栈与 MINIX 的解药完全同构（MINIX 的 INET server 重生同样不承诺 exactly-once，同样靠协议幂等与 journal）。差异在反方向：MINIX 的代价是"全有或全无"（整个 server 陪葬全部连接与缓冲），栏栈靠 R1 落点控制 + 胶囊边界可把陪葬范围设计得小一到两个数量级。**在副作用一致性上栏栈不声称超越 MINIX，声称的是：同样的外物（journal/硬件环/协议幂等），更小的牺牲半径。**

## 正确性补全协议：四件

全 create 化 + 独立裁决者模型在推演中暴露出四个正确性缺口，均以小机制钉死：

**① Park-and-Ack 静默协议（多核）**。Pause 清 run bit 只防"将来被调度"，防不了"正在执行的这个时间片"——若故障核仍在自旋读写 capsule，memset 就是数据竞争。协议：裁决核向故障核发定向 NMI → 故障核 park handler（十几行、0 unsafe：置位 + 自旋）置 `park_ack` → 裁决核有界等待（~100μs），等不到（连 NMI 都进不去 = TCB 级损坏）则降级 BHR；恢复完成后 IPI 唤醒 parked 核重定向到新入口。单核场景该协议天然退化掉：NMI 已物理抢占故障代码，静默自动成立。

**② InitCtx 受限 token**。`Domain::new()` 在关中断的恢复上下文运行，必须禁拿共享锁 / 禁分配 / 禁碰他域——不靠纪律靠类型：init_fn 只收 framework 构造的 `&mut InitCtx<'_>`，token 只暴露"读 static 配置、写自己域的 slot 与 BCB 状态位"，不携带任何全局锁入口。**API 面即权限面**，new() 在恢复上下文死锁在结构上不可能。

**③ 裁决页表自笼头**。裁决页表只映射：BCB 原子槽位区 + 故障域 capsule buffer。即使那 500 行里真藏了 bug，想碰健康域的内存 = page fault——**静默损坏变成响亮失败**。这里 MMU 不做遏制（遏制归编译器），做的是对裁决者自身错误的第二道防线。

**④ 二级 watchdog**。裁决流程自身也是一段会执行的程序：为其设第二级 watchdog 窗口，裁决超时（例如被 TCB 级损坏拖死）→ 硬复位。BHR 终态，语义仍然确定。

## 执行形态：单核与多核

"按需借核 + 变身 + 归还"的形态与 Intel SMM（SMI → 进 SMRAM 隔离空间 → 执行 → RSM 归还）同构——区别在本设计把这套硬件范式**在内核层用纯软件重演**：NMI + CR3/TTBR0 切换 + 一套平时不映射的页表，不依赖任何固件或平台特权。这是"免特殊硬件"立场的落地关键：需要的是硬件*能力*（标配），不是硬件*设施*（专属）。

| 场景 | 恢复路径 | 粒度与代价 |
|---|---|---|
| 多核（任意架构） | 借核变身裁决，故障核 park-and-ack | 外科手术；其余域全程不停 |
| 单核 x86_64 / aarch64 | NMI / FIQ 不可屏蔽 → 同核原地裁决，改写中断返回帧重定向新入口 | 外科手术；全系统冻结几十 μs |
| 单核 RISC-V 低端（无可屏蔽中断） | 无入场机会 → watchdog 硬复位 | 整机冷启动；create 化保证重启后重建语义确定，配合日志文件系统恢复快 |

## 性能论证与速率预算

**热路径**：所有权是编译期检查，零运行时开销。跨域调用的实际记账：Inline 快照一次 `store(Release)` ≈ 10-20ns + lookup 的 gen-check ≈ 1-5ns，合计 **<30ns**——约等于一次函数调用加一条分支。对照 MINIX 跨服务 IPC 往返 1-5μs，**快 50-100 倍**。"零开销遏制"的兑现数值是"零到不用计"。

**机制本体**（多核借核裁决，不含域自身 new()）：

| 阶段 | 延迟 | 主要成本 |
|---|---|---|
| park 握手 | ~0.3-1μs | 一次跨核缓存行转移 |
| 变身（CR3 切换 + 冷启动） | 1-5μs | TLB refill / ICache 冷 |
| arbitrate 纯函数 | 1-3μs | 读若干原子槽位（远端脏行每个 ~200ns） |
| memset buffer | 1-10μs | 4KB≈1μs，64KB≈10μs |
| BCB 回收 + gen++ + 唤醒 | ~2μs | 原子批量 + 一次 IPI |
| **合计** | **~10-20μs** | 大变量只剩 new() 本身 |

**端到端 MTTR**：panic / 不变式类故障 = 检测 <1μs + 机制 ~20μs + new()，合计几十~百 μs 量级；livelock 类 = watchdog 策略窗口主导（10ms-1s 可调），机制成本是零头；驱动域设备 reset（ms~s，NVMe / PHY 有规格书下限）是 MINIX / Linux 同样要付的物理成本，栏栈不在此维度作弊。

**横比**：

| 系统 | 一次服务级故障恢复 | 恢复粒度 |
|---|---|---|
| Linux panic | 秒~分钟（整机重启 + fsck） | 整机 |
| MINIX 3 重生 | ~1-10ms（拆进程 + spawn + execve + 重 init） | 进程级，全状态丢失 |
| 栏栈（目标态） | 计算域 ~10-100μs；驱动域 ms 级（贴硬件下限） | 亚进程级，可只重建单个结构 |

比 MINIX 快 1-2 个数量级的来源很朴素：MINIX 重生要**造一个新进程**（地址空间构建 + ELF 装载 + 调度入队），栏栈重建只是 memset 一块早就在那的静态 buffer + 调一次 new()。

**两拍重建（world-stop 上限承诺）**：rebuild 拆两拍——第一拍在裁决上下文内只做结构部分（memset + new() 结构初始化 + gen++，μs 级），域以 `Degraded` 上线；第二拍设备 reset 序列在后台 work queue 跑完，原子置 `Healthy`（消费者 gen-check 顺带查 health 位）。由此"任何一次裁决造成的世界停止 ≤50μs"成为硬承诺，单核场景也不被 ms 级设备重置拖成长冻结。

**内核内 IPC**：无硬件切换（无 syscall / 异常），低于真微内核的跨组件 IPC 成本。

## 故障注入实证：模型选择与验收标准（初步解）

"fault-injection 实证恢复语义成立"是三条先河前提中唯一可由单人 + QEMU + 零外部许可闭环的一条。本节是初步研讨得到的实证方案，有待实际执行检验。

### 把"恢复语义成立"拆成三个可分离命题

| 命题 | 内容 | 检验手段 | fault injection 的角色 |
|---|---|---|---|
| A 遏制层 | 故障域损坏不出自身 capsule | **静态**：services 0 unsafe 审计 + R5 边界审计 | 不归它管——遏制是编译期不变式，对抗性注入无法反驳一段编译不出来的代码 |
| B 机制活性 | 任意故障后裁决→重建→归还全流程跑通 | 受控注入（非随机采样） | 主场 |
| C 语义正确性 | 重建后的世界 == 新启动 | 注入 + oracle | 主场，全部难度浓缩在 oracle 设计 |

随机注入在故障空间（Σ 域 × 操作边界 × 故障类型）里覆盖率趋近于零，B 的正确做法是**受控选择**：按故障模型逐个定向触发，每个模型至少一个确定性用例进 CI。

### 首选模型：livelock + watchdog NMI

四种故障模型的验证效力不对等：

| 模型 | 注入手段 | 覆盖面 | 判定 |
|---|---|---|---|
| **Livelock（关中断死循环）** | 域内 `loop { spin_loop() }` 不返回 + watchdog NMI 触发 | **全链路一次覆盖**：不可屏蔽检测 → park-and-ack → 借核变身 → arbitrate → memset+new()+gen++ → 拉取式失效 → 归还核 | **首选** |
| Panic/abort | 现有 `maybe_inject_fault` 概率 panic | 只测恢复段（走 IDT 本核入口），不触发远程裁决 | 语义等价 oracle 的低成本载体，进 CI 每 PR 跑 |
| 越界写 | guard page 外显式写 | 只测 Verdict=Pass 短路分支 | 补充覆盖 |
| 静默数据损坏 | QEMU monitor `memwrite` 位翻转 | 检测层盲区 | **不投入**——safe Rust 下不崩溃的"算错"不在恢复机制管辖内，注入它只能暴露检测无能，无正向验证力 |

livelock 之所以是首选，因为 **Path 2 相对普通 panic recovery 的全部设计增量都集中在"关中断的死循环核如何被另一颗核远程仲裁并恢复"这条路径上**。其余模型各测一段或测不了；livelock 单用例跑通 = 三 crate 分工、静默协议、全 create 化、拉取式失效全部被真实执行路径覆盖。

```rust
// SIMPLIFIED: livelock 最小注入用例骨架; 单域单故障; 待扩至多域并发/多架构
#[cfg(feature = "fault_injection")]
fn livelock_inject() -> ! {
    loop { core::hint::spin_loop(); }   // 不 panic、不返回、纯忙等
}
// watchdog NMI（另一核，或单核同核）→ arbiter 变身 → Rebuild
// 断言: 恢复后经陈旧 Handle 的 lookup 返回 Err(Recovered)
```

### Oracle 四类

"恢复语义成立"的重音在"成立"——凭什么说恢复了。重生流派的 oracle 是：**"域的正确状态"不是故障前那一刻，而是 fresh boot 后应有的状态**。全 create 化把这个哲学承诺压缩成机械可判定的不变式：*重建完成瞬间，capsule buffer 内容 == 纯 `new()` 产出的内容——内存相等，无需语义理解*。

| # | Oracle | 检验 | 实现成本 |
|---|---|---|---|
| 1 | **等价类**：恢复后 dump capsule buffer，与无故障对照 run 逐字节比对（哈希即可） | 命题 C 核心"恢复 == 新启动"；buffer 不等即暴露 R5 审计漏的状态逃逸 | 极低（buffer 是 framework 静态分配，内核自 dump） |
| 2 | **不变式**：陈旧 Handle lookup 必 `Err(Recovered)`、gen 恰 +1、InitCtx token 未逃逸、未登记外部资源归 BCB 队列 | 信任链每一环 | 低（原子读检） |
| 3 | **FS 差分**：每笔写 n 个边界逐点崩溃，恢复后跑文件一致性校验 | 通道 3（new() = journal replay） | 中（`host-tests/src/fsx.rs` 是现成模型，扩展"中途崩溃+恢复"即可） |
| 4 | **网络分区模拟**：注入后掐断/延迟对端流量，验证会话重连 | 通道 1（已发送 ≡ 分区） | 中（smoltcp vendored 自带 phy 层 `FaultInjector`） |

### 验收标准：不变式而非恢复率

现有 chaos harness 的 "recovery rate ≥ 80%" 是 undo/补偿流派的统计式验收（多数故障被救活即通过）。栏栈的宣称是结构式的（恢复边界 = buffer 边界），结构式宣称要么 100% 要么设计有洞——**验收标准随之换为四条 100% 不变式**：

1. 重建后 buffer 与纯 new() 等价（oracle 1）；
2. 陈旧引用必拒（oracle 2）；
3. gen 每重建恰好 +1，不多次不跳号；
4. world-stop 在 ≤50μs 预算内实测（速率预算章的兑现检验）。

任一不变式违反 = 设计有洞，立即停工修复；统计式百分比反而掩盖结构缺陷。现有 `tests/chaos/` harness 属 undo 时代遗产，接线随全 create 化落地时重写（已隐含在该决策的迁移成本中）。

### 实证的管辖边界（诚实声明）

fault injection 证不了遏制层（那是编译器的活，命题 A 静态审计），也证不了静默损坏（那是类型系统的活）。它证的是**恢复机制的活性（B）+ 重建语义的等价性（C）**。"实证恢复语义成立"的精确含义即此，不多承诺。
